Designing with AI

Design Process

How I move from concept to working product

Overview

I take product ideas from concept to solution. My process combines product thinking, visual design, front-end prototyping, and structured documentation to reduce ambiguity before implementation. AI accelerates exploration and execution, while I remain responsible for defining the direction, evaluating tradeoffs, reviewing the work, and deciding what belongs in the final product.

Workflow focus

  • Define the product direction
  • Translate ideas into working interactions
  • Evaluate technical and design tradeoffs
  • Document behavior and implementation intent
  • Prepare the work for stakeholder and engineering review

Defining the product

To gain clarity, I'll sketch to work out interactions between iterative design passes

I begin by clarifying the problem, audience, constraints, and intended outcome. Sketching helps me work through interactions away from the screen, while AI helps surface missing states, challenge assumptions, and compare possible directions. I use those inputs to define the product structure, refine the hierarchy, and decide what should move forward before investing in high-fidelity design or code.

Discovery Methods:

  • Concept development
  • AI-assisted discovery
  • Sketch interpretation
  • Interface architecture
  • Feature definition
  • Design critique

Reasoning through ambiguity

I treat conversation with AI as a structured reasoning process rather than a one-step prompt. I establish the product context, document prior decisions, define constraints, and use targeted questions to expose tradeoffs, test assumptions, and identify missing requirements. The value is not the first answer; it is the ability to make the problem clearer, compare alternatives, and move toward a decision with the relevant context preserved.

Building a working prototype

I use VS Code to edit prototypes and perform code reviews.

I translate approved design direction into working HTML, CSS, and JavaScript prototypes developed in GitHub branches. This lets me evaluate responsive behavior, component states, transitions, motion, and data visualizations that static screens cannot fully communicate. I direct the implementation, review the structure in the browser and code, test each iteration, and make targeted edits when a simpler or more accurate solution is needed.

What I prototype

  • Responsive interfaces
  • Interactive behaviors
  • Component states
  • Panel transitions
  • Motion studies
  • Data visualizations
  • Internal design tools

Live Prototype: Design Inspector

After spending years collaborating on product strategy, working with individual stakeholders to validate final designs, and handing off high-fidelity mockups and development specifications to engineering teams, one pattern became clear: repeatable validation workflows still required significant scheduling, explanation, clarification, and alignment time. I created the Design Inspector prototype to help multiple teams envision what inspecting their part of the design-validation workflow relevant to them might look like, review on their own time, provide approval with greater context, and focus meetings on the decisions that truly require collaboration.

Design Inspector scope

  • Inspectable components
  • Curated design intent
  • Runtime class collection
  • Lightweight token annotation
  • State documentation
  • Accessibility guidance
Goal

Make the relationships between visual design, interaction behavior, accessibility, and implementation easier for the product team to understand.

Preparing for implementation

Pushing bug fixes in Github

Once an experience has been evaluated, I convert the approved decisions into structured documentation and implementation guidance. Depending on the product, that may include product briefs, feature and behavior specifications, functional requirements, accessibility notes, code examples, GitHub branches, and documented bug fixes. The handoff includes more than polished screens: it gives the team a working model of the experience and a clear record of how it should behave.

Handoff deliverables

  • Product briefs
  • Feature specifications
  • Behavior specifications
  • Functional requirements
  • Accessibility notes
  • Code examples
  • Implementation guidance

Judgment over generation

AI increases the range and speed of work I can execute, but judgment remains the control layer. I decide which problem should be solved, which constraints matter, whether a recommendation supports the product goal, and when the work is ready to move forward. I validate output through visual review, interaction testing, code inspection, and comparison with established requirements, rejecting or redirecting solutions that add unnecessary complexity.

What remains human-directed

  • Problem definition
  • Product priorities
  • Design quality
  • Technical tradeoffs
  • Final approval
Result

AI expands execution capacity; I remain accountable for the product decisions, design direction, and quality of the final experience.

Reflection

This process has expanded how far I can carry a product idea without losing the design intent along the way. I can define the problem, shape the interface, prototype the behavior, inspect the implementation, and document the decisions in one connected workflow.

“The value is not generation alone. It is the ability to move from an unclear idea to a working, reviewable, and documented product direction.”
